# 单张参考图分析

## 用途

把一张与当前任务相关的图片拆成可使用的视觉信息，并明确它究竟是最终生成输入、分析来源、上下文，还是不应参与生成。

## 何时读取

只有当语义分析已经确认当前任务确实需要这张图片时才读取。消息里虽然带图、但图片与当前提示词无关时，不读取本页，按纯文字输入处理。

## 第一步：先判运行职责

先从用户当前提示词判断这张图在**最终真正执行生图时**是否仍需要被提供给模型。

### GENERATION_INPUT

最终生成仍要使用这张图，例如：

- 待编辑原图 / canvas；
- 人物身份参考；
- 产品身份参考；
- 服装、姿态、场景、构图或风格参考；
- 角色资产、写真、海报或新场景生成时仍需绑定原人物身份。

这类图片会影响最终 Finalizer：至少存在一张 `GENERATION_INPUT` 时，最终走 Edit grammar。

### ANALYSIS_SOURCE

图片只用于：

- 反推 Prompt；
- 拆解构图、镜头、光影、材质；
- 提炼可复用视觉公式；
- 观察后生成一份以后可脱离原图独立使用的 Prompt。

这类图可以参与分析，但**不会因为当前存在附件就让最终 Prompt 自动走 Edit**。若最终生成不再依赖图片，则走 T2I grammar。

### CONTEXT_ONLY

图片只帮助理解当前会话背景，但用户没有要求在最终生成中继承任何可见属性。只提取理解当前任务真正需要的信息，不建立生成绑定。

### IRRELEVANT

图片与当前提示词没有语义关系，可能是误接、历史附件或用户已经切换到新任务。完全忽略，不进入 Reference、Prompt 或 Finalizer Route。

## 第二步：若为生成/分析相关图片，再判具体职责

可用职责包括：

- 成片参考；
- 人物身份参考；
- 场景参考；
- 服装或道具参考；
- 姿态与动作参考；
- 构图与镜头参考；
- 光影与色彩参考；
- 风格参考；
- 首帧、尾帧或关键帧参考；
- Prompt 反推分析源。

一张图可以承担多个具体职责，但必须区分主职责与辅助职责。

## 分析顺序

1. 用户当前提示词究竟想用这张图做什么；
2. 它属于 `GENERATION_INPUT / ANALYSIS_SOURCE / CONTEXT_ONLY / IRRELEVANT` 哪一类；
3. 图中哪些元素决定主体辨识度；
4. 观众第一眼看哪里；
5. 场景的前中后景和主体位置；
6. 景别、机位、焦段感、透视和裁切；
7. 主体动作、姿态、接触和视线关系；
8. 光源方向、阴影软硬、色温和主体分离；
9. 皮肤、布料、金属、玻璃、颗粒等材质表现；
10. 风格由哪些线条、渲染、色彩或摄影变量实现；
11. 哪些内容必须保留、修改、只借用或禁止继承。

## 风格提取原则

当用户只借用参考图风格时，优先提取：

```text
色彩结构
+ 构图关系
+ 镜头与透视
+ 光影方向
+ 材质表现
+ 媒介或渲染方法
```

不要把原人物、原服装、原场景和原道具误当成风格的一部分。

风格提取后应转换为当前任务可执行的关系，而不是只给“复古、电影感、韩漫”等标签。

## 参考强度

只对真正需要继承的职责判断：

- 高保留：主体、构图和关键视觉关系尽量接近；
- 中保留：保主体与气质，允许改镜头、场景、服装或光影；
- 低保留：只借用局部结构、风格或某个元素。

`ANALYSIS_SOURCE` 的“分析精度高”不等于“最终生成高保留”；两者不要混淆。

## 视频参考帧附加判断

如果参考图用于视频首帧、尾帧或关键帧，还要识别：

- 哪些元素可以运动；
- 哪些身份、服装、场景和道具必须固定；
- 当前动作处于起势、过程还是落点；
- 镜头后续可能向哪个方向运动；
- 哪些构图边缘需要给运动留空间。

输入层只提取这些锚点，具体帧结构仍由视频参考帧 Playbook 决定。

## 冲突优先级

```text
用户当前文字要求
→ 用户明确指定的必须保留项
→ 当前图片的运行职责
→ 参考图主职责
→ 参考图辅助信息
→ 自动补全
```

## 内部草稿

下面只用于内部分析，不直接决定对外输出结构：

```text
运行职责：GENERATION_INPUT / ANALYSIS_SOURCE / CONTEXT_ONLY / IRRELEVANT
参考图主职责：
辅助职责：
必须保留：
必须修改：
允许变化：
只借用：
禁止继承：
第一视觉落点：
空间与构图要点：
镜头与透视要点：
光影与色彩要点：
材质与风格实现：
视频用途附加锚点：
```

无视频用途时省略最后一项。最终展示格式仍由 mode output contract 决定。

## 任务联动

输入分析完成后，继续读取唯一任务 Playbook：

- 复现、结构提炼或改造 Prompt → `../tasks/prompt-reverse-engineering/playbook.md`；
- 整体画面改写 → `../tasks/image-to-image/playbook.md`；
- 局部修改，或已有成片只补皮肤微观纹理 / 保真细节增强 → `../tasks/image-editing/playbook.md`；
- 角色、场景、分镜或视频参考帧 → 对应任务 Playbook。

任务 Playbook 决定“做什么”，最终是否 T2I / Edit 仍由最终生成是否依赖 `GENERATION_INPUT` 决定。

## 常见失败与修复

- 有附件就当生成参考：先做语义相关性和运行职责判断；
- 反推图误进 Edit：若最终 Prompt 可独立执行，把图片标成 `ANALYSIS_SOURCE`；
- 误带图片污染 Prompt：标成 `IRRELEVANT` 并完全忽略；
- 什么都保留：回到当前任务目标，删除无关锚点；
- 只复述图片：补“如何用于当前任务”的转换关系；
- 改写后主体漂移：增加身份和关键外观锚点；
- 风格与内容混在一起：分别列出风格实现和可替换主体；
- 猜测设备或身份：只描述可见结果，不把推测写成事实。
