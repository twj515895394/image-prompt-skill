# 多张参考图分析

## 用途

为多张与当前任务相关的图片分配清晰职责，处理冲突和优先级，避免把所有附件平均融合，更不能把无关图片误绑定进最终生成。

## 何时读取

用户提供两张或以上图片，并且语义分析确认至少两张图片与当前任务相关时读取。

如果消息里虽然有多张附件，但只有一张真正相关，应改走单图输入；如果全部无关，应按纯文字输入处理。

## 第一步：先判每张图的运行职责

每张附件先独立归类：

```text
GENERATION_INPUT
- 最终生成时仍需把该图提供给模型
- 例如 identity、canvas、outfit、pose、scene、style reference

ANALYSIS_SOURCE
- 只用于反推、拆解、比较、提取构图/光影/风格规律
- 最终 Prompt 可以脱离该图执行

CONTEXT_ONLY
- 只帮助理解上下文
- 不参与最终生成

IRRELEVANT
- 与当前提示词无关
- 误接、历史附件或已经失效的图
- 完全忽略
```

**只有 `GENERATION_INPUT` 才进入最终 Reference Role Map 和图片标签。**

Finalizer Route 由最终图片依赖决定，而不是总附件数：

```text
GENERATION_INPUT_COUNT >= 1 → Edit
GENERATION_INPUT_COUNT = 0 → T2I
```

例如：三张图都只是让 Agent 分析风格并产出一份独立 Prompt，最终仍然是 T2I；两张图里一张人物身份、一张服装都要在生成时继续引用，则是 Edit。

## 第二步：识别用户意图

先判断用户是在做：

- 同一人物的一致性延续；
- 人物与服装组合；
- 人物与场景组合；
- 多人物分别绑定参考；
- 构图、姿态或动作借用；
- 光影或风格迁移；
- 局部物体替换；
- 多图整合后的新创作；
- 多图比较、分析或反推；
- 其中部分图片实际上与当前任务无关。

## 第三步：只给相关图片分配具体职责

可用职责包括：

- canvas；
- 人物 A 身份；
- 人物 B 身份；
- 脸部与五官；
- 体型与比例；
- 发型；
- 妆容；
- 服装；
- 姿态与动作；
- 场景与空间；
- 道具；
- 构图与镜头；
- 光影与色彩；
- 材质；
- 风格；
- 局部细节；
- 分析源；
- 负面参考：明确哪些错误不能继承。

不要用“主图负责全部、辅图只补细节”作为固定模板。职责必须服务用户当前目标。

## 第四步：绑定对象

多人物或多来源生成任务必须明确：

```text
人物 A ← 哪张 GENERATION_INPUT 提供身份、服装和姿态
人物 B ← 哪张 GENERATION_INPUT 提供身份、服装和姿态
场景 ← 哪张 GENERATION_INPUT 提供空间
构图 ← 哪张图提供镜头关系
风格 ← 哪张图只提供视觉表现
```

不得把人物 A 的脸、人物 B 的服装和第三张图的姿态无意混合到同一个角色上。

`ANALYSIS_SOURCE / CONTEXT_ONLY` 可以帮助理解，但不能被写成 `<imageX>` 生成绑定；`IRRELEVANT` 完全不参与。

## 第五步：处理同维度冲突

同一维度由多张相关图片提供不同答案时：

1. 用户明确指定者优先；
2. 与当前任务目标最相关者优先；
3. 身份参考与风格参考分离；
4. canvas 与素材来源分离；
5. 不能同时成立的要求必须做取舍；
6. 无法判断且会显著改变结果时，交互模式只追问一个最关键问题；快速模式按最小风险默认值裁决。

## 第六步：确定保留强度

对每张相关图片分别标记：

- 必须精确保留；
- 保留主要特征；
- 只借用局部；
- 只借用风格或方法；
- 仅分析、不进入生成；
- 不继承图中其他内容。

## 图片标签与 Finalizer 的关系

只有 Edit Finalizer 才需要考虑图片标签。

- 只有 1 张 `GENERATION_INPUT`：自然称“图像 / 图片中 / the image”，不强制 `<image1>`；
- 有 2 张及以上 `GENERATION_INPUT`：在支持显式 image tag 的目标模型中，按最终生成输入重新编号为 `<image1>`, `<image2>`…；
- 原消息附件编号不等于最终生成标签编号；`ANALYSIS_SOURCE / CONTEXT_ONLY / IRRELEVANT` 被排除后，应按实际 generation inputs 连续编号；
- 每个标签必须绑定唯一职责，防止跨属性污染。

## 内部草稿

下面只用于内部分析，不直接决定对外输出格式：

```text
附件 1 运行职责：
附件 2 运行职责：
附件 3 运行职责：

Generation Input Map：
<image1>：
<image2>：

对象绑定：
必须保留：
必须修改：
允许融合：
禁止混合：
冲突处理：
最终参考优先级：
```

如果最终 `GENERATION_INPUT_COUNT = 0`，不建立 `<imageX>` Map，转为 T2I Finalizer。

## 常见失败与修复

- 附件全部平均融合：先做运行职责，再分配具体维度；
- 分析图被写成生成标签：`ANALYSIS_SOURCE` 只用于理解；
- 误带图片污染人物或背景：标为 `IRRELEVANT`；
- 平均融合导致谁都不像：重新分配单一职责；
- 人物串脸或串衣服：补对象绑定；
- 风格图改变人物身份：明确风格图不提供身份；
- 场景图污染人物外观：限制场景图只提供空间和光影；
- 原附件编号与最终标签编号混淆：只对 generation inputs 连续重新编号；
- 多图要求互斥：按用户目标确定主优先级，不强行兼容。
