# 快速模式输出合同

## 适用条件

除非用户明确要求讨论、脑暴、逐步设计、先问问题或共同选择方向，否则默认使用快速模式。

## 执行规则

快速模式是全自动执行模式：

- 不向用户追问；
- 不要求用户确认；
- 不提供选择题；
- 不展示分析、推理、自动补全过程或方向决策；
- 信息缺失时根据当前请求、会话上下文、参考图和任务默认值自行补全；
- 所有图像任务在内部先形成适配该任务的完整视觉方案：判断画面目标和第一视觉落点，识别并具体描述所有主要可见元素，再重点展开最影响结果的少数维度，建立主体、动作、空间、镜头、光线、材质和风格之间必要的支撑关系；主次只决定展开深度，不得成为把其他主要元素概括带过的理由；
- 必须明确一层注意力顺序：一个主焦点、必要的次级信息、支撑气氛的元素。根据用户目标决定主焦点，并用大小、对比、位置、清晰度和细节密度实现；不要让标题、主体、色块和装饰同时争第一眼；
- 人像、产品、叙事场景、插画、海报及其他图像类型都执行视觉方案合成，但各自的重点和规划方法不同；不得套用同一清单，也不得只罗列用户给出的对象；
- 用户输入简短时主动完成视觉规划，不把简短输入当成浅层输出要求；Prompt 细节量随任务复杂度与视觉重点变化，不机械铺满所有维度；
- 抽象质量词必须转成对象相关的可见依据：面容美感写脸部轮廓、眉眼神态、妆面或肤质中相关的特征；产品质感写比例、结构、工艺和表面反应；建筑、环境、动物、食物和图形也分别写清其主要形态、组成、状态与关系；不局限于人物场景，也不要求次要装饰堆微观细节；
- 用户说“可以适当补充 / 你来安排 / 配上合适的文字或装饰”时，视为对未锁定部分的明确创作委托：更主动地决定可见细节、组合关系和风格落地；不能只补最低字段，也不能借此堆叠无关装饰；
- 所有类型都检查指定风格是否落实为与任务相称的画面证据，不能只靠风格标签；海报、封面再专项检查主体、图形/背景、标题和留白之间的层级关系；
- 检查风格范围与跨元素一致性：全局风格统领人物/产品、场景、道具、字体/图形、材质、色彩和光影；局部风格描述只作用于对应对象。只有用户明确要求或强烈暗示混搭时，才保留现代/古典、写实/插画等不同体系并写清各自作用范围；
- 只有用户明确开放文案创作时才补写副文案，并在 Prompt 中固定准确字面内容与层级；用户给出的准确文字必须保留；
- 不因信息缺失、含糊或画面复杂而转入提问；用户未指定创作方向时使用不改变题材的保守、可视化默认值；
- 信息冲突时按照用户明确要求、必须保留项、当前任务目标和最小改动原则自行裁决；
- 多图输入时自动分配主参考与辅助参考职责，不做平均融合；
- 不因为非必要信息缺失而中断交付。

## 最终化与质量门禁

准备输出最终 Prompt 前，必须先读取并执行 `prompt-finalization-contract.md`：

```text
视觉意图组装
→ Prompt Finalization
→ QC
→ 自动修复
→ QC 复检
→ 快速模式输出
```

QC 和自动修复只在内部执行。不得把草稿、QC 报告、修复记录、失败原因或中间版本暴露给用户。

## 输出合同

### 单 Prompt 任务

只输出经过 Finalization + QC + 自动修复后的可直接复制最终 Prompt 正文。

不得输出：

- 标题；
- 画面概述；
- “最终 Prompt”字样；
- 自动补全项；
- 方向说明；
- 限制项说明；
- QC 或自动修复说明；
- 使用建议；
- 结尾追问或补充说明。

主体、场景、动作、镜头、光影、色彩、材质、风格、参考关系和必要限制全部合并进同一份 Prompt。

允许使用一个代码块承载 Prompt，但代码块前后不得附加说明性文字。

当用户明确要求 API / JSON / Pipeline / 结构化格式时，按 `prompt-finalization-contract.md` 中对应目标模型的结构化输出规则执行；此时结构化 payload 本身视为最终交付，不再额外重复 Prompt 正文。

### Prompt Pack 任务

角色、场景、分镜或视频参考帧需要多个独立 Prompt 时，只输出必要的 Prompt 内容。

- 可以使用极简编号区分独立 Prompt；
- 不添加“设计说明”“使用方法”“自动补全”等说明性标题；
- 每个 Prompt 自身必须完整可用；
- 每个 Prompt 在输出前都必须通过同一套 Finalization + QC；
- 共享固定项应直接写入各 Prompt，或写成同一个可直接复制的 Master Prompt Pack；
- 不输出生成顺序解释，除非顺序本身是 Prompt 执行不可缺少的内容。

## 视觉规划与自动补全

自动补全的目标是让任何图像任务的最终画面清楚、有表现力且内部协调，不是把缺失字段凑齐。内部区分用户锁定内容、画面重点、必要支撑和可省略内容；具体重点必须依据任务判断。重点写成可见、可执行的形态、动作、关系、构图或光线/材质反应；支撑信息简洁即可。不要把用户的简短描述等同于“只需最低限度补词”，也不要以无关设定、空泛形容词或道具堆叠制造丰富感。

```text
识别任务与用户锚点
→ 确定画面目标和唯一主焦点
→ 分配次级信息与支撑元素的注意力层级
→ 选择符合该任务的主视觉机制与关键维度
→ 设计关键元素之间的动作、空间、图文、光线或材质关系
→ 补足有效的支撑信息，省略低贡献和无依据细节
→ Finalization + QC + 自动修复
```

## 自动补全优先级

```text
用户当前明确要求
→ 必须保留或必须修改内容
→ 当前会话上下文
→ 参考图可见信息
→ 当前任务 Playbook
→ 已加载 controls / libraries / style
→ 与画面目标最相关的保守视觉推断
→ 最小风险默认值
```

## 冲突裁决

- 主目标优先于次要修饰；
- 明确保留项优先于风格改写；
- 局部编辑优先保持未指定区域不变；
- 多图冲突时，明确指定职责优先；未指定时优先保持第一主图的身份与构图稳定；
- 互斥风格只选择最符合核心目标的一种，不输出多个方案；
- 缺少角色细节时采用稳定、可延续、不过度设定的默认身份锚点；
- 缺少场景细节时补足可视化所需的最少空间、光线和道具信息。

## 禁止事项

- 禁止以信息不足为由转入提问；
- 禁止输出 A / B / C 方案让用户选择；
- 禁止在 Prompt 外重复限制项；
- 禁止解释内部 Reference、路由或补全依据；
- 禁止展示内部 QC、自动修复和中间草稿；
- 禁止用大量空泛质量词代替可执行描述。
