# 2026-08 角色身份参考板验证（含 2026-09 三分区修订）

## 验证目标

验证 `character-assets` 对三分区角色身份参考板的路由、版式、输入兼容和高风险失败限制，同时确保不破坏现有快速 / 交互模式和默认加载预算。

## 固定预期

```text
画布：1920 × 1080，16:9
布局：22% + 22% + 56%
右侧：单一 Face Close-up

第 1 列：正面全身，唯一去头区域；无头、无脸、无头发
第 2 列：完整背面全身；包含后脑与发型后部；严格不露脸
第 3 区：3/4 正常表情头部 Close-up，只含头部、发型与发饰，不含颈部、肩线或服装
变体：微笑、左转 45°、右转 45°分别生成完整三分区图
```

第 3 区使用整块右侧大区，必须优先保证脸型、五官比例、发际线和皮肤细节的可见面积，不因追加第二个表情而缩小或分割人脸。

## 正向回归

### Case 1：单张简单人物参考图生成三分区角色设计图 Prompt

用户请求：

```text
参考这张人物照片，给我生成一份三分区角色设计图的图片编辑 Prompt。
```

预期：

- 输入：`single-image-reference`
- 任务：`character-assets`
- 按需读取身份一致性 control
- 参考图是人物照片，必须同时读取 `anti-ai-realism`，把 Close-up 皮肤五变量写入 Prompt
- 不读取 `fidelity-detail-enhancement`
- 输出一份完整三分区 Prompt，不拆成三个互相独立的角色
- 第一列必须明确去掉完整头部
- 第二列必须明确保留完整后脑和发型后部
- 第 3 区只保留一个正常表情，且只展示头部、发型和发饰，不出现颈部、肩线或服装
- 若用户需要微笑或其他朝向，输出对应的独立三分区变体规则
- 默认采用 1920×1080、22% + 22% + 56%

结果：规则覆盖。

### Case 2：无参考图、只有人物文字描述

用户请求：

```text
设计一个 35 岁中国男性侦探的三分区角色参考板，短发，瘦高，灰色风衣。
```

预期：

- 输入：`text-input-expansion`
- 任务：`character-assets`
- 快速模式不因缺少精确五官而追问
- 自动补全稳定、不过度设定的脸型和五官锚点
- 第一列无头无脸；第二列保留短发后脑
- 第 3 区只生成一个正常表情头部 Close-up，不出现颈部、肩线或服装
- 未声明写实、也没有真人照片时，不强制加载 `anti-ai-realism`

结果：规则覆盖。

### Case 3：参考图 + 泛称“角色图”自动命中三分区

用户请求：

```text
参照图1的人物特征生成一张角色图。
```

预期：

- 输入：`single-image-reference`
- 任务：`character-assets`
- 自动采用三分区角色设计图，不要求用户额外说“角色设计图”或“三分区”
- 参考图只提供人物身份与外观，不继承参考图中的场景背景
- 三个区使用纯灰白无纹理摄影棚背景、柔和棚拍光和轻微接地阴影

结果：规则覆盖。

### Case 4：用户明确要求先确认角色外貌

用户请求：

```text
我没有参考图，想做一个古代女性角色的四区设定图，先问我需要确认的外貌信息。
```

预期：

- 进入交互模式
- 每次只问一个最高影响变量
- 推荐顺序：年龄感与气质 → 脸型 / 关键五官 → 发型、发色与后脑结构 → 身材比例 → 主服装与配色
- 用户要求直接出结果时立即停止追问

结果：规则覆盖。

## 关键错误回归

### Case 5：禁止把两列 Body Panel 都做成无头

错误输出：

```text
第一列正面无头
第二列背面无头
```

必须判定为失败。

修复要求：

```text
只有第一列去头。
第二列必须从后脑到鞋底完整入镜，包含后脑、头部和发型后部，但严格背对镜头、不露脸。
```

### Case 6：禁止第一列出现正面小脸

第一列如果出现完整头部、半张脸、头发残留或可识别五官，必须判定为失败。

### Case 7：禁止第二列转头露脸

第二列允许并要求完整后脑，但如果人物回头、露侧脸、露眼鼻嘴或形成第二张人脸身份参考，必须判定为失败。

### Case 8：禁止布局退化成 2×2

在用户未指定其他版式时，四区角色身份参考板若输出 2×2 等分网格，必须判定为不符合默认布局。

正确默认：

```text
两个全高纵向 Body Panel：22% + 22%
右侧大 Face 区：56%
Face 区上下 50 / 50
```

### Case 9：脸部变体导致换脸

微笑或左 / 右 45°独立三分区变体如果改变脸型、眼距、鼻唇比例、发际线、主要发型或人物年龄感，应判定为身份一致性失败。

### Case 10：默认人脸区出现多个表情

默认三分区设计图如果在第 3 区同时出现中性和微笑等多个表情，应判定为版式失败。修复为只保留一个正常表情；其他表情单独生成完整三分区变体。

### Case 11：写实三分区板缺少皮肤控制

参考真人照片生成三分区角色设计图时，若 Prompt 只写「真实皮肤」「perfect skin」或把 Face Close-up 写成磨皮陶瓷脸，必须判定为失败。

修复要求：读取 `anti-ai-realism.md`；Close-up 分开写半哑光基调、T 区高光和区域纹理；颈、手不得比脸更光滑。

### Case 12：动漫角色误加真人毛孔

用户明确要求二次元 / 像素 / 插画角色设计图时，不应加载 `anti-ai-realism` 的皮肤五变量。

### Case 13：禁止继承参考图背景

三分区角色设计图如果照搬参考图的房间、街道、风景、道具或彩色背景，应判定为背景控制失败。修复为纯灰白无纹理摄影棚背景、柔和棚拍光和轻微接地阴影。

### Case 14：特写区混入颈部或服装

第 3 区如果生成胸像、肩部以上构图，或出现颈部、肩线、领口、服装、胸部等头部以下内容，应判定为特写职责失败。修复为只展示头部、发型、发饰、耳部和脸部，下边界贴近下颌线且不露颈；服装与身体比例只由第 1 区和第 2 区展示。

## 相邻任务反向回归

以下请求不应默认套用三分区角色板：

- “给我一张电影感人物写真” → `finished-image`
- “给角色做正侧背三视图” → `character-assets` 的普通三视图路线
- “做 8 种表情表情板” → `character-assets` 的表情板路线
- “只把人物衣服换成西装” → 按整体图生图或局部编辑目标判断，不因有人物自动使用三分区板

## 加载预算

典型三分区请求保持：

```text
1 input
1 character-assets task
0–2 controls
写实真人：identity-consistency + anti-ai-realism
stylized / 非写实：identity-consistency，必要时 continuity 或 reference-handling
0–2 libraries
0–1 style
0–1 diagnostic
```

写实三分区板不要再叠加 `fidelity-detail-enhancement`，也不要为皮肤新建第三份 control。

无需创建单独的三分区 layout control，避免同一规则出现第二份正文真源。

## 结论

三分区角色身份参考板应把以下约束视为不可混淆的结构规则：

```text
ONLY PANEL 1 IS HEADLESS.
PANEL 2 MUST INCLUDE THE REAR HEAD BUT MUST NOT SHOW THE FACE.
```

中文等价规则：

```text
只有第一列去头；第二列必须有后脑，但绝对不能露脸。
```

写实真人三分区板额外要求：身份控制之外必须加载 `anti-ai-realism`，Face Close-up 按皮肤五变量写，不得只写「真实皮肤」。
