# 通用服装设计图验证

## 验证目标

确认服装设计板能稳定进入专用 `fashion-design` task，同时人物身份参考板、时尚人像成片和局部换装继续进入原有任务；确认用户要求的三视图、去识别模特、细节和材质规则均有唯一正式正文。

## 正向用例

### Case 1：纯文字服装款式板

请求示例：用户描述一套短款西装与直筒裤，要求生成 9:16 服装设计图、正侧背全身视图、细节特写和面料样片。

预期：

- 输入：`text-input-expansion.md`；任务：`fashion-design/playbook.md`。
- 主视图为同一模特穿着同一套服装的正面、严格侧面和背面完整全身像。
- 模特脸去识别化；细节特写对应主图真实结构；材质样片对应服装部位。
- 款式细节不足时只做服装类型一致的克制补全，不发明品牌、成分或额外装饰。

结果：规则与路由审查通过。

### Case 2：服装参考图转设计板

请求示例：用户提供一张服装照片，要求按图保留廓形、领型、袖口和配件，整理成正侧背服装设计参考板。

预期：

- 输入：`single-image-reference.md`；任务：`fashion-design/playbook.md`。
- 参考图只绑定服装设计；原人物身份与脸部不继承。
- 可见剪裁、配色、材质线索和装饰一致；未展示区域只作最小延续，不添加参考图没有的元素。

结果：规则与路由审查通过。

## 反向用例

### Case 3：角色身份三视图

请求示例：用户要求同一人物的正面、背面和侧面角色设定图，重点保持脸型、发型和身份一致。

预期：`character-assets`；不得加载 `fashion-design`，不得把人物脸模糊或替换成无五官人台。

结果：反向路由审查通过。

### Case 4：时尚人像成片

请求示例：用户要求模特穿设计师套装在街头拍一张品牌宣传照，不需要三视图或设计细节。

预期：`finished-image`；不得强制加服装三视图、材质样片和参数信息区。

结果：反向路由审查通过。

### Case 5：局部换装编辑

请求示例：用户要求将现有人像的外套换成参考图中的款式，脸、姿态和背景保持不变。

预期：`image-editing`；不得把画面重构成服装设计板。

结果：反向路由审查通过。

## 加载预算与模式合同

- 默认：1 input + 1 task。
- 按需：材质选型或复杂冲突最多加 1 library / control，不加载角色身份与真人皮肤控制作为默认项。
- 快速模式：最终只输出一份经过 Finalization + QC 的完整服装设计 Prompt。
- 交互模式：仅用户明确要求讨论或确认时启用；不新增强制追问。

## 静态检查状态

- `git diff --check`：待最终改动完成后运行。
- `python scripts/check_reference_integrity.py`：待最终改动完成后运行。
- GitHub Actions `Reference Integrity`：待推送 PR 后检查最新 Head。
- 本文验证的是任务边界、规则覆盖与加载预算，不声称已完成真实图像模型的端到端画质验证。
